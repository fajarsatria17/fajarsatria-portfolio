## 2. Directory Responsibilities

### `public/`
Static files copied to the build output root without processing. Items here have predictable, stable URLs. The CV PDF lives here with a stable filename so the download link never breaks between rebuilds.

### `src/assets/`
Images and fonts **processed by Vite** — Vite adds content hashes to filenames for cache busting. The owner's avatar goes here (will be bundled/hashed). The hero WebGL fallback image also lives here.

### `src/components/`
All reusable, composable React components. Organized into sub-directories by functional domain:
- `hero/` — Complex Hero Section components with 3D + content separation
- `navigation/` — Navbar, mobile menu, nav links
- `ui/` — Design system primitives (Button, Badge, Card, etc.)
- `projects/` — Project card and filter components
- `timeline/` — Reusable timeline for experience and education
- `contact/` — Contact form and info display
- `layout/` — Page layout wrappers (Footer, PageLayout)
- `seo/` — SEO head management

### `src/sections/`
Homepage section components that compose multiple `components/` primitives. Each section corresponds to a visual section of the homepage (`AboutSection`, `SkillsSection`, etc.). Sections are "smart" in that they read from `src/data/`.

### `src/pages/`
Route-level page components. Each corresponds to a React Router route. Pages compose sections and handle page-level SEO via `SEOHead`.

### `src/scenes/`
Exclusively Three.js / React Three Fiber scene components. Isolated from the rest of the UI so the 3D code can be tree-shaken and lazy-loaded without polluting the main bundle.

### `src/data/`
Single source of truth for all portfolio content. TypeScript files export typed arrays/objects. These are the files the owner edits to update content. No CMS required.

### `src/hooks/`
Custom React hooks. Each hook has a single responsibility. `useReducedMotion` and `useWebGLSupport` are especially critical for the Hero Section's progressive enhancement strategy.

### `src/utils/`
Pure functions with no React dependencies. These are easily unit-tested and handle date formatting, slug operations, content filtering, and CSS class merging.

### `src/types/`
TypeScript interface definitions shared across the application. `content.ts` defines all data model interfaces. No circular dependencies.

### `src/styles/`
Global styles loaded once at app initialization. `tokens.css` defines the design token CSS custom properties that Tailwind's configuration references.

### `src/lib/`
Thin wrappers around third-party services. Isolates external service configuration from components, making it easier to swap providers.

### `tests/`
Mirrors the `src/` directory structure. Separated into `unit/`, `integration/`, and `e2e/` by test level.

## 3. Naming Conventions

| Item | Convention | Example |
|---|---|---|
| React Components | PascalCase | `HeroSection.tsx`, `ProjectCard.tsx` |
| Hooks | camelCase with `use` prefix | `useReducedMotion.ts` |
| Utils | camelCase | `date.ts`, `cn.ts` |
| Types/Interfaces | PascalCase | `Profile`, `Project`, `SiteSettings` |
| Data files | camelCase | `profile.ts`, `projects.ts` |
| CSS classes (Tailwind) | Tailwind utilities | `flex items-center gap-4` |
| CSS custom properties | `--kebab-case` | `--color-accent`, `--spacing-section` |
| Test files | Same as source + `.test.ts(x)` or `.spec.ts` | `ProjectCard.test.tsx` |
| E2E spec files | kebab-case + `.spec.ts` | `homepage.spec.ts` |
| Barrel exports | `index.ts` per directory | Re-exports from directory |
| Environment variables | `SCREAMING_SNAKE_CASE` | `VITE_SITE_URL`, `RESEND_API_KEY` |

## 4. Import Path Strategy

Configure path aliases in `vite.config.ts` and `tsconfig.app.json`:

```ts
// tsconfig.app.json
{
  "compilerOptions": {
    "paths": {
      "@/*": ["./src/*"],
      "@components/*": ["./src/components/*"],
      "@sections/*": ["./src/sections/*"],
      "@pages/*": ["./src/pages/*"],
      "@data/*": ["./src/data/*"],
      "@hooks/*": ["./src/hooks/*"],
      "@utils/*": ["./src/utils/*"],
      "@types/*": ["./src/types/*"],
      "@styles/*": ["./src/styles/*"]
    }
  }
}
```

**Usage:**
```ts
import { Button } from '@components/ui';
import { profile } from '@data/profile';
import { useReducedMotion } from '@hooks/useReducedMotion';
```

This avoids fragile relative paths like `../../../../utils/date`.

## 5. Barrel Export Pattern

Each directory with an `index.ts` re-exports its contents:

```ts
// src/components/ui/index.ts
export { Button } from './Button';
export { Badge } from './Badge';
export { Card } from './Card';
export { ExternalLink } from './ExternalLink';
// ...
```

This keeps imports clean while maintaining component file isolation. Avoid barrel exports for lazily-loaded modules (like 3D scenes) to preserve code splitting.
